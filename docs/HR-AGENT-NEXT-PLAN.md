# iclaw HR Agent 工作台下一阶段搭建计划

## 状态更新：第三轮治理与导入已落地

- 工作区设置已支持 `hr_agent_enabled`，owner/admin 可开启或关闭 HR Agent 能力；
  保存后 runner 安全重启，下次会话热生效。
- `/hr` 活动流改为“最近操作”，`source` 明确区分为 `agent_runtime`、`web`、`system`
  或 `unknown`；页面操作不再伪装成聊天操作。
- Boss/OpenCli 外部命令链路已下线。本地上传保留，新增 iclaw 服务端 HTTPS 直链导入；
  链接导入有 SSRF、重定向、MIME、大小和超时保护。
- 候选人新增手动三轮面试官字段，可填写、清空并同步飞书。
- 已关闭候选人支持保留期提示和显式确认硬删除；硬删除会先删除远端 Bitable record，
  失败时中止本地删除。

## 状态更新：JD 聊天闭环已补齐

- 新增 `hr_get_job`，Agent 可读取完整 JD、结构化要求、岗位漏斗和规则摘要。
- 新增 `hr_analyze_job`，只读分析 JD 质量并写 `job_analyzed` 审计，不覆盖 JD。
- 新增 `hr_update_job`，使用 `expected_updated_at` 做乐观并发控制；需要显式确认。
- JD 文本更新会归档 draft/active 规则；标题更新会复用候选人飞书同步计数。
- 聊天第一版不能通过该工具修改岗位状态、到期时间、软删除或恢复。

## 状态更新：第二轮已落地

- HR-first 首屏已生效：`/` 与未知路由默认进入 `/hr`，权限不足时也回落到 HR 工作台。
- `/hr` 总览已新增“最近聊天操作”，读取脱敏审计摘要，展示 Agent 阶段变更、飞书同步
  成功和岗位生命周期事件。
- 新增 `GET /api/hr/agent-activity`，按 `candidate_stage_updated`、`feishu_synced`、
  `job_expired`、`job_soft_deleted`、`job_restored` 过滤审计日志。
- 软删除 JD 已在 store 与 REST 层禁止更新；候选人、简历、评分和反馈历史继续保留。
- 新增 workspace 级 `hr_agent_enabled`（默认启用）。关闭后 runner 不注册 `hr_*` 工具，
  host-side IPC 也会拒绝 HR capability。
- 第一轮提到的全局聊天 HR 工具、JD 到期/软删除、HR 页面收敛均已完成；项目保持
  单人独立自托管定位，不引入协作角色。

## 基线结论

当前项目已经完成 HR 可演示闭环，但从“可演示 MVP”到“可稳定自托管产品”之间仍有明确缺口。下一阶段不建议继续横向堆业务页面，应优先补齐演示稳定性、持久化任务、真实集成验证、页面收敛和 Agent 工具边界。

## 当前已完成

- 核心 HR 闭环：JD、简历导入、解析、JD 匹配、证据链、缺失能力、面问题、反馈规则、看板、人才库和诊断。
- AI 异步入口：重新分析返回后台执行状态，候选人列表和详情可轮询运行、完成、失败。
- 模型输出治理：结构化 prompt、Zod 校验、宽松输出归一化、JSON 截断后一次紧凑重试、失败不写虚构评分。
- 候选人去重：同岗位内按邮箱、手机号、简历 SHA-256 复用候选人并追加简历版本。
- 飞书能力：绑定页、字段映射、连接测试、字段类型检查、类型安全转换、中文阶段、评分数字、完整推荐理由、payload hash 幂等。
- mock 演示模式：`ICLAW_HR_MOCK_MODEL` 已覆盖简历解析、JD 匹配、面问题、反馈分析和岗位诊断；演示数据可从 `data/jd` 与 `data/resume` 重复导入。
- 持久化 AI 任务：候选人分析已进入 `hr_analysis_jobs` 队列，支持启动恢复、自动重试、任务列表和手动重试。
- 测试基线：HR 相关 8 个测试文件、48 项测试通过；`npm run typecheck`、`npm run docs:check`、`npm run build:web` 均通过。

## 主要不足

### 1. 异步任务的真实重启演练仍不足

`hr_analysis_jobs` 已有队列字段、启动恢复、指数退避和手动重试 API，但仍需要用长运行服务和真实中断场景做验收，并补充跨进程并发锁定测试。

### 2. 真实外部集成未验收

飞书同步代码和测试较完整；真实 Bitable 创建、更新、重复同步、禁用配置、字段误映射、凭证错误和权限错误已有一轮验收，但仍要纳入升级回归。Boss/OpenCli 外部命令已按定位下线，后续只维护 HTTPS 直链与本地上传。

### 3. 面试演示数据和真实飞书验收仍需收口

`ICLAW_HR_MOCK_MODEL` 和演示数据脚本已实现，但飞书真实 Bitable E2E、同步成功/失败页面状态演练和演示前 checklist 还需要最终验收。

### 4. 页面体系仍双轨

候选人详情、岗位详情和推面看板已迁移到 `web/src/pages/hr/`；旧 `HrWorkbenchPage` 已删除，
`/hr/board` 保留为兼容路由并指向新看板。HR 请求集中在 `web/src/pages/hr/api.ts`，
主导航不再保留推面看板入口。

### 5. Agent 工具层未建立

当前 AI 主要用于表单触发的结构化分析。还没有可被 Agent 安全调用的 `hr_list_jobs`、`hr_get_candidate`、`hr_update_candidate`、`hr_sync_candidate_to_feishu` 等能力。

### 6. 协作与治理较薄

数据按 `owner_user_id` 隔离，符合单人独立定位；面试官是自由文本，不引入账号授权。
数据保留期、硬删除和审计摘要已落地，仍需长期运行中的 PII 保留策略和备份演练。

## 方向判断

第一阶段继续坚持“个人自托管 HR Agent 工作台”，不做通用商业 ATS，不接入实时薪酬行情，不新增绕过 Pi Agent Runtime 的模型调用。

补足顺序应是：

1. 先保证面试可稳定演示：mock 模型、演示数据、真实飞书验收。
2. 再保证工程可靠性：持久化 AI 任务、恢复、重试、观测。
3. 然后收敛产品入口：候选人详情、岗位详情、看板和导航统一。
4. 最后扩展 Agent 化、协作和输入源能力。

## Phase 1：演示稳定与真实集成收口

目标：断网或无稳定模型凭证时也能完成完整演示，真实飞书路径可复现。

### 工作项

1. 新增 `ICLAW_HR_MOCK_MODEL`：
   - 默认 `false`；
   - 只在 HR AI 调用入口生效；
   - 输出固定简历画像、匹配证据、评分、5-8 个面问题、反馈分析和岗位诊断；
   - 输出仍经过现有 Zod 校验、落库、状态流转和飞书 payload 生成。
2. 新增演示数据脚本：
   - 后端、网络安全 2 个岗位；
   - 6-10 份代表性简历；
   - 至少 2 条面试反馈；
   - 至少 1 条待审核和 1 条已激活 JD 偏差规则；
   - AI 成功、失败、飞书同步成功、同步失败四类状态。
3. 飞书真实验收：
   - 创建新候选人；
   - 更新阶段；
   - 相同 payload 重复同步不重复建记录；
   - payload hash 变化后更新；
   - 停用配置后显示未同步或待验证；
   - 覆盖 App Secret 错误、缺权限、Table ID 错误、候选人 ID 字段缺失、评分映射单选、结论映射数字、公式字段不可写。
4. 文档补充：
   - mock 启动和关闭方法；
   - 飞书表字段类型要求；
   - 演示前 checklist 和演示后清理步骤。

### 验收

- `ICLAW_HR_MOCK_MODEL=true` 时无需真实模型即可完成上传、AI 分析、面问题、阶段流转、飞书 payload 同步。
- 真实 Bitable 验收记录可复现，失败原因能在页面和脱敏日志中解释。

## Phase 2：持久化 AI 任务队列

目标：AI 分析不再依赖进程生命周期，失败可解释、可重试、可观测。

### 数据模型

扩展 `hr_analysis_jobs`，建议复用现有 `status` 作为队列状态，避免再加一个容易漂移的 `queue_status`：

- `status = queued | running | completed | failed | retrying`
- `next_retry_at`
- `locked_at`
- `locked_by`
- `lease_expires_at`
- `max_attempt`
- `last_error`
- `started_at`
- `finished_at`

### Worker 与 API

1. 后端启动 worker：
   - 启动时把孤儿 `running` 标记为 `retrying` 或 `failed`；
   - 按创建时间或岗位顺序消费；
   - 支持最大重试和指数退避；
   - 锁定任务防止同进程重复执行；
   - 服务停止时安全中断当前任务。
2. 统一 API：
   - `GET /api/hr/analysis-jobs?status=queued|running|retrying|failed|completed`
   - `POST /api/hr/analysis-jobs/:jobId/retry`
   - `POST /api/hr/jobs/:jobId/analyze-pending`
3. 前端新增 AI 任务页：
   - 队列状态、重试次数、下一步重试时间、失败原因、目标候选人；
   - 单任务手动重试；
   - 岗位级批量分析待处理候选人。

### 验收

- 服务重启后没有长期 `running` 任务。
- 失败任务有 `last_error`、attempt、目标候选人，并能手动重试。
- 批量导入后前端只看任务进度，不再串行等待每个模型响应。

## Phase 3：新旧 HR 页面收敛

目标：消除双入口，统一状态、样式、请求和数据类型。

### 工作项

1. 新建候选人详情页，迁移旧页面中的：
   - 简历列表、预览、替换、删除；
   - AI 分析和错误展示；
   - 阶段流转；
   - 面试反馈；
   - 飞书手动同步。
2. 新建岗位详情页，迁移旧页面中的：
   - JD 编辑；
   - 简历批量导入；
   - Boss/OpenCli 导入；
   - 岗位规则草稿审核；
   - 岗位统计与诊断。
3. 旧路由兼容：
   - `/hr/board` 跳转到新候选人中心或独立新看板；
   - `/hr/jobs/:jobId` 跳转到新岗位详情；
   - `/hr/candidates/:candidateId` 跳转到新候选人详情。
4. HR 主导航收敛为：
   - 总览、岗位库、候选人、问题库、AI 任务、诊断、飞书。
5. 平台导航归类：
   - 智能体、能力库、任务保留；
   - 用量不在 HR 主工作流突出展示；
   - 渠道、插件保留在平台能力区。

### 验收

- 用户从任意旧 HR URL 进入都能到达新页面。
- 候选人和岗位详情不再从旧 1600 行页面读取重复状态。
- 前端 HR API 请求集中在共享层，避免页面间字段名和状态解释不一致。

## Phase 4：HR Agent 工具层

目标：让 Agent 能操作 HR 数据，但所有访问仍继承用户身份、owner 隔离和审计。

### 分批开放

1. 只读工具：
   - `hr_list_jobs`
   - `hr_get_job_stats`
   - `hr_list_candidates`
   - `hr_get_candidate`
2. 受控写入：
   - `hr_update_candidate`
3. 外部同步：
   - `hr_sync_candidate_to_feishu`

### 安全边界

- 工具输入使用 Zod 校验。
- 每次调用绑定当前用户，强制 `owner_user_id` 过滤。
- 阶段枚举必须在服务端校验。
- 修改和同步复用现有 API 层业务逻辑、审计和飞书幂等逻辑。
- 工具结果返回脱敏摘要，不直接暴露简历全文、手机号或邮箱。
- 能力库展示工具描述、输入输出、权限边界和启用状态。

### 验收

- 跨 owner ID 查询返回 404 或权限错误，不泄露存在性。
- Agent 只能在用户有权限的岗位和候选人范围内操作。
- Agent 修改阶段后审计日志和飞书行为与 REST 路由一致。

## Phase 5：协作与数据治理

目标：从单 HR 扩展到小型招聘团队，同时降低简历 PII 风险。

### 最小角色

- `owner`：管理岗位、候选人、飞书配置和成员。
- `reviewer`：查看指定岗位候选人和匹配结果，提交面试反馈。
- `viewer`：只读指定岗位数据。

### 数据模型

- 新增岗位成员或 HR 协作成员表。
- 候选人增加可选 `assignee_user_id` 和 `interviewer_user_id`。
- 简历、评分、反馈、同步状态按岗位授权过滤。

### 治理

- 支持候选人关闭后保留期。
- 支持手动删除候选人时同步删除简历文件、评分、问题、反馈和同步状态。
- 审计日志保留操作事实，日志中的 PII 脱敏。
- 增加安全测试：未登录、跨 owner、简历下载越权、飞书配置越权、日志 PII 泄漏。

## Phase 6：输入源治理与诊断增强

目标：维护受控简历输入源，并把诊断从计数升级为决策解释。

### 简历输入源

1. 保持本地上传为第一导入链路。
2. 维护 HTTPS 直链导入的 SSRF、重定向、MIME、大小和超时防护。
3. 不解析 Boss 动态页面，不引入爬虫。
4. 增加导入失败原因和重试可观测性。
5. 定期演练 PII 文件清理与备份恢复。


### 诊断

1. 阶段转化率和平均停留时间。
2. 拒绝原因分布。
3. JD 覆盖缺口。
4. 面试反馈新增要求。
5. 面试官评分一致性。
6. AI 失败率和岗位健康度。
7. 只使用系统内数据，不接入实时薪酬或外部市场行情。

## 总验收标准

- HR 可完成 JD、简历、AI 匹配、面问题、反馈、阶段流转、飞书同步闭环。
- mock 模式下完整流程可演示，且不会写虚构业务数据。
- 服务重启后任务状态可恢复或明确失败，可手动重试。
- 真实飞书创建、更新、幂等和错误场景均有验收记录。
- 旧 HR 路由不再承载重复实现。
- HR Agent 工具通过 Pi Agent Runtime 能力体系访问，不绕过权限和审计。
- 数据保留、owner 隔离和安全测试通过后维持单人自托管定位。
